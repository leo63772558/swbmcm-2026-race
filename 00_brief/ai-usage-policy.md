# AI 工具使用合规（官方强制）

> 依据：《数维杯人工智能工具使用规定（2026 修订）》，2026-11-11 起施行。
> 完整核验见 `rules-conflict-rulings.md`；本文件只讲**这个仓库里怎么执行**。

## 一、六项义务，逐项对应到文件

| 官方要求 | 在本仓库怎么落地 |
|---|---|
| ① 论文内**声明**是否使用 AI | 论文里单独一句声明；未使用则写「本参赛队未使用任何 AI 工具」 |
| ② References 里**列出** AI 工具 | 格式：`[编号] 工具名称，版本/型号，开发机构/公司，使用日期` |
| ③ 正文相应位置**标注** | 在借助了 AI 的段落处加注，指向 ②中的编号 |
| ④ 提交《AI 工具使用情况报告》 | 从 `08_ai-log/AI_USAGE_LOG.csv` 直接汇总生成，**不占 25 页配额** |
| ⑤ **程序注释**标注 | 代码里被 AI 显著改写的函数，文件头注释写明"AI 辅助：工具 + 日期" |
| ⑥ **核心工作队员独立完成** | 见下面第二节，这是最硬的一条 |

## 二、不能交给 AI 的四件事

《规定》点名核心工作必须由队员独立完成。落到 B 题就是：

| 环节 | 谁能做 |
|---|---|
| **模型假设与构建**（为什么这样假设、忽略什么、边界怎么定） | 只能队员 |
| **算法设计与求解思路**（P2(2) 用什么目标函数、P4 怎么设计场景集） | 只能队员定方案，AI 可写实现 |
| **模型推导**（P2 的精度公式、P3 的误差传播链） | 只能队员 |
| **结果解读与结论推导**（这个反常结果说明什么、部署建议怎么写） | 只能队员 |

AI 可以做：把队员定好的模型写成代码、跑数值、画图、排版、格式自检、查错。
**判断点由队员拍板**，AI 只列候选方案与代价。

## 三、定量红线

- 全文**疑似 AIGC > 30%** → 判雷同，取消评奖资格
- 全文**总相似比（含引用）> 50%** → 判雷同，取消评奖资格

所以：论文正文必须自己组织语言。AI 给的句子只能当"结构和句式参考"，不能整段照抄。
交稿前自己跑一遍 AIGC 检测与查重，超过阈值就重写超标的段落。

## 四、台账怎么记

文件：`08_ai-log/AI_USAGE_LOG.csv`，**每次交互结束后追加一行**。

| 字段 | 怎么填 |
|---|---|
| `工具名称` | 如 `WorkBuddy Agent` / `ChatGPT（Codex）` |
| `版本/型号` | 如 `DeepSeek-V4.1-Flash` / `GPT-6` |
| `开发机构/公司` | `深度求索` / `OpenAI` |
| `使用日期` | `YYYY-MM-DD` |
| `使用环节` | 拆题 / 建模 / 求解 / 出图 / 写作 / 排版 / 自检 |
| `关键提示词` | 一句话概括你让它干什么 |
| `输出要点` | 它产出了什么 |
| `采纳内容` | 实际用了哪些；**没采纳就写"未采纳"** |
| `人工修改情况` | 队员改了哪里（这一栏是自查 AIGC 比的依据） |
| `对应章节或文件` | 追到具体路径 |
| `操作人` | 队员代号 |

## 五、最容易忘的两处

1. **代码注释里也要标**。支撑材料里的 `.py` 文件，AI 辅助的部分要写明，否则报告与材料对不上。
2. **参考文献里 AI 工具是独立条目**，不要把工具混进学术文献里、也不要在正文里只写"使用了 AI"却不给编号。
