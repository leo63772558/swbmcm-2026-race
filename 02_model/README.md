# 02_model — 建模文档（人写，AI 只提建议）

这个目录是**论文正文的骨架**，不是草稿堆。四问的模型必须队员自己写，AI 只能：
- 新建 `_draft-*.md` 提候选方案（不改已有正文）
- 检查符号一致性、公式与代码是否对得上
- 指出逻辑跳跃与未说明的假设

## 文件顺序（按这个顺序写，不要跳）

| 文件 | 内容 | 状态 |
|---|---|---|
| `00-decomposition.md` | 四问分解：输入 / 决策变量 / 约束 / 目标 / 输出形态 + 候选方法与可算性 | ⏳ 进行中 |
| `01-assumptions.md` | 全局假设与简化，每条写清"为什么可以这样假设、否则代价是什么" | ⬜ |
| `02-notation.md` | **符号表（唯一准绳）**。公式与代码里的符号必须与它逐字一致 | ⬜ |
| `P1.md` … `P4.md` | 各问的模型、推导、算法、结果解读 | ⬜ |

## 三条硬规矩

1. **符号表先行**。任何公式出现前，符号必须在 `02-notation.md` 里有定义。
   `02-notation.md` 由队长统一维护，其他人只提修改请求，不直接改。
2. **一个符号只表示一个量**。`θ` 在题面里是告警方位角，就不能再拿来当别的角。
   如果必须复用（比如文献里的习惯），写成 `θ_alert` / `θ_inc` 这种带下标的。
3. **假设要能被证伪**。写"忽略车辆转向时间"可以，但要写清题面本身就允许忽略（题面 §Vehicle 明说不计加减速与转向）。

## 写作口径

- 模型假设、推导、结论**必须队员自己写**（见 `00_brief/ai-usage-policy.md` 第二节）
- 数学符号用 LaTeX：`$Q = 1/r$`、`$\sigma(s) = a + bs$`
- 每个结论后标注数字来源，例如「（见 `04_results/p1_stations.csv`）」
- 不要写"我们认为可能是……"这类空话，写清适用条件与失败情形
